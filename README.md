# Media Server Docker Stack

This repository runs a media automation stack with Cloudflare Access in front of its administrative web applications. Plex remains directly accessible on port 32400, qBittorrent is available only on the server's LAN-bound HTTPS entrypoint, and WireGuard provides authenticated remote access to LAN-only services.

## Services

| Service | Purpose | Exposure |
|---|---|---|
| Traefik 3.7 | Reverse proxy and ACME DNS certificates | TCP 443 bound to `LAN_IP`; port 80 is Docker-internal |
| cloudflared | Outbound Cloudflare Tunnel connector | No host port |
| Plex | Media streaming | TCP 32400 direct; local HTTPS through Traefik |
| qBittorrent + Gluetun | VPN-isolated downloads | LAN HTTPS only; BitTorrent ingress uses PIA port forwarding |
| Sonarr, Radarr, Lidarr, Bazarr, Prowlarr, Tautulli | Media automation | Cloudflare Tunnel + Access |
| wg-easy 15 | WireGuard server and management UI | UDP 51820 direct; UI through Cloudflare Access |
| Minecraft | Two vanilla servers | `LAN_IP` only; reachable remotely through WireGuard |

Traefik uses a static dynamic configuration generated by Docker Compose. It does not have Docker socket access. Services are separated into purpose-specific networks, and tunneled routers accept origin traffic only from the fixed `cloudflared` container address.

## Important security boundaries

- Configure a Cloudflare Access application for every tunneled hostname. Also enable **Protect with Access** in each Tunnel route's additional application settings so `cloudflared` validates the Access JWT.
- Do not forward TCP 80, TCP 443, TCP 25565, TCP 25566, or TCP/UDP 6881 at the internet router. TCP 443 and the Minecraft ports bind only to `LAN_IP` as an additional safeguard.
- The intended WAN ingress is Plex TCP 32400 and WireGuard UDP 51820.
- Plex currently retains its configured LAN-wide `allowedNetworks` authentication exception. Any unauthenticated device in that subnet is treated by Plex as the owner; this is an explicitly accepted risk.
- qBittorrent runs in Gluetun's network namespace. The PIA-assigned listening port is synchronized through Gluetun's port-forward hooks and is never published on the home server.
- Administrative config files should be owner-only. Run the host-hardening installer in [SETUP.md](SETUP.md) after reviewing it.

## Updates

Updates remain fully automatic, but no container has Docker API access. A host systemd timer runs [scripts/update-containers.sh](scripts/update-containers.sh) at 03:00 local time. It retains old images and explicitly recreates qBittorrent after a Gluetun image change.

The following moving release channels are intentional:

- Traefik `v3.7` for compatible security patches
- wg-easy `15` for compatible v15 updates
- LinuxServer, cloudflared, Gluetun, and Minecraft stable/latest channels

Minecraft itself is pinned to the currently deployed game version (`26.2`) so an image refresh cannot silently upgrade the worlds.

## Storage layout

Set `ROOT_MEDIA_DIR` to a directory with this structure:

```text
/mnt/media/
├── downloads/
│   ├── complete/
│   └── incomplete/
├── movies/
├── tv/
├── music/
└── transcode/
```

All download and automation services use `/data`, preserving hardlinks and atomic moves. Plex mounts `/data` read-only, with only `/data/transcode` overlaid writable at `/transcode`.

Persistent application state lives below `/opt/docker`. wg-easy v15 uses `/opt/docker/wg-easy-v15`; the prior `/opt/docker/wg-easy` directory is deliberately retained for migration and rollback.

## Common operations

```bash
docker compose config --quiet
docker compose up -d --remove-orphans --wait
docker compose ps
docker compose logs -f SERVICE
```

Use the scheduled updater manually with:

```bash
sudo ./scripts/update-containers.sh
```

See [SETUP.md](SETUP.md) for migration, Cloudflare, firewall, permissions, and validation steps.
