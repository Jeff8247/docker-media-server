# Media Server Docker Stack

This repository runs a media automation stack with Cloudflare Access in front of its administrative web applications. Plex remains directly accessible on port 32400, qBittorrent is available only on the server's LAN-bound HTTPS entrypoint, and WireGuard provides authenticated remote access to LAN-only services.

## Services

| Service | Purpose | Exposure |
|---|---|---|
| Traefik 3.7 | Reverse proxy and ACME DNS certificates | TCP 443 bound to `LAN_IP`; port 80 is Docker-internal |
| cloudflared | Outbound Cloudflare Tunnel connector | No host port |
| Plex | Media streaming | TCP 32400 direct; local HTTPS through Traefik |
| qBittorrent + Gluetun | VPN-isolated downloads | LAN HTTPS only; BitTorrent ingress uses PIA port forwarding |
| Sonarr, Radarr, Lidarr, Bazarr, Prowlarr, Tautulli | Media automation | Cloudflare Tunnel + Access |
| Beszel | Host and Docker monitoring with historical charts and alerts | Cloudflare Tunnel + Access only |
| wg-easy 15 | WireGuard server and management UI | UDP 51820 direct; UI through Cloudflare Access |
| Minecraft | Two vanilla servers | `LAN_IP` only; reachable remotely through WireGuard |

Traefik uses a static dynamic configuration generated by Docker Compose. It does not have Docker socket access. Services are separated into purpose-specific networks, and tunneled routers accept origin traffic only from the fixed `cloudflared` container address.

## Important security boundaries

- Configure a Cloudflare Access application for every tunneled hostname. Also enable **Protect with Access** in each Tunnel route's additional application settings so `cloudflared` validates the Access JWT.
- Restrict each administrative Access application, including `beszel.${DOMAIN}`, to the owner's exact email address. Do not use an `Everyone`, email-domain, or broad bypass policy. The configured one-time PIN login then rejects other email addresses before traffic reaches the application.
- Do not forward TCP 80, TCP 443, TCP 25565, TCP 25566, or TCP/UDP 6881 at the internet router. TCP 443 and the Minecraft ports bind only to `LAN_IP` as an additional safeguard.
- The intended WAN ingress is Plex TCP 32400 and WireGuard UDP 51820.
- Plex currently retains its configured LAN-wide `allowedNetworks` authentication exception. Any unauthenticated device in that subnet is treated by Plex as the owner; this is an explicitly accepted risk.
- qBittorrent runs in Gluetun's network namespace. The PIA-assigned listening port is synchronized through Gluetun's port-forward hooks and is never published on the home server.
- The Beszel agent is the only container with Docker API access. Its Docker socket mount is read-only and is used to collect per-container metrics; treat this as privileged monitoring access and do not expose the agent socket outside the host.
- wg-easy v15 has only `NET_ADMIN`; it cannot load or unload host kernel modules and cannot access `/lib/modules`. The Debian host loads the required WireGuard and netfilter modules at boot as described in [SETUP.md](SETUP.md).
- Administrative config files should be owner-only. Run the host-hardening installer in [SETUP.md](SETUP.md) after reviewing it.

## Updates

Updates remain fully automatic without granting an updater container Docker API access. A host systemd timer runs [scripts/update-containers.sh](scripts/update-containers.sh) at 03:00 local time. It retains old images and explicitly recreates qBittorrent whenever the Gluetun container is replaced.

The following moving release channels are intentional:

- Traefik `v3.7` for compatible security patches
- wg-easy `15` for compatible v15 updates
- LinuxServer, cloudflared, Gluetun, and Minecraft stable/latest channels

Minecraft itself is pinned to the currently deployed game version (`26.3`) so an image refresh cannot silently upgrade the worlds.

## Monitoring

Beszel provides host and per-container CPU, memory, disk, network, temperature,
uptime, and historical metrics. Its dashboard is available only through
Cloudflare Access at `https://beszel.${DOMAIN}`. Port 8090 remains internal to
Docker and is not published on the host.

The hub and local agent communicate through
`/opt/docker/beszel/socket/beszel.sock`; no agent TCP port is exposed. Persistent
hub and agent state lives below `/opt/docker/beszel`. The untracked `.env` must
define `BESZEL_AGENT_KEY` using the hub's public SSH key. A token is optional for
the local hub-initiated Unix-socket connection.

After a new installation, create the Beszel administrator account and add the
local system with:

```text
Name: MediaServer
Host / IP: /beszel_socket/beszel.sock
Port: blank
```

For remote access, add `beszel.${DOMAIN}` as a Cloudflare Tunnel published
application pointing to `http://traefik:80`, then create a Cloudflare Access
self-hosted application for the same hostname. Its Allow policy should include
only the owner's exact email address using the existing one-time PIN login
method.

## Storage layout

On this server, set `ROOT_MEDIA_DIR=/mnt/media/plex`. The media RAID is mounted
at `/mnt/media`, with the application-visible data below it:

```text
/mnt/media/plex/
├── downloads/
│   ├── complete/
│   └── incomplete/
├── Movies/
├── TV/
├── Audio/
└── transcode/
```

All download and automation services use `/data`, preserving hardlinks and atomic moves. Plex mounts `/data` read-only, with only `/data/transcode` overlaid writable at `/transcode`.

Persistent application state lives below `/opt/docker`. Protected, recurring,
off-host backups must include all of `/opt/docker`, the untracked `.env`, the
media filesystem, and the relevant host storage/firewall configuration. In
particular, the wg-easy v15 database and generated WireGuard configuration live
in `/opt/docker/wg-easy-v15`. See the backup and restore procedure in
[SETUP.md](SETUP.md).

On this Debian 13 deployment, WireGuard is supplied by the host's 6.12 kernel as a loadable module. Keeping module loading on the host lets wg-easy operate with less privilege while retaining the `NET_ADMIN` capability required to create and configure its WireGuard interface.

## Common operations

```bash
docker compose config --quiet
docker compose up -d --remove-orphans --wait
docker compose ps
docker compose logs -f SERVICE
```

Use the scheduled updater manually with:

```bash
sudo ./scripts/update-containers.sh
```

See [SETUP.md](SETUP.md) for deployment, Cloudflare, firewall, permissions, and validation steps.

After changing peers or server settings, verify that wg-easy has synchronized the expected configuration with the live WireGuard interface:

```bash
docker exec wg-easy wg show
```

The output should show the expected server public key and a `peer:` entry for every configured client.
